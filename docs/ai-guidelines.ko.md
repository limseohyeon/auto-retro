# AI 개발 가이드

## 목적

이 저장소는 사람이 제품 방향과 중요한 결정을 승인하고 지원되는 coding agent가 조사, 계획, 구현, 검증, 문서화를 수행하는 방식으로 개발한다. `AGENTS.md`는 coding agent가 읽는 공통 실행 규칙이고, 이 문서는 그 규칙을 실제 개발 과정에서 운용하고 개선하는 방법을 설명한다.

규칙 자체는 품질을 보장하지 않는다. 품질 기준은 가능한 한 테스트, 빌드, Flyway 제약조건, Spring Modulith 검증, CI처럼 실행 가능한 형태로 만든다.

## 기본 개발 흐름

```text
요구사항과 완료 조건 합의
→ 관련 코드·문서·테스트 조사
→ 작은 수직 기능 단위로 구현
→ 집중 검증
→ 전체 verifyAll 검증
→ 사람이 diff와 결과 승인
```

작은 수정은 대화 안에서 계획하고 바로 처리한다. 여러 모듈, 데이터 마이그레이션, 외부 연동 또는 여러 작업 세션이 필요한 변경은 `docs/exec-plans/active/`에 실행 계획을 남긴다.

## 문서 선택과 기록 원칙

문서는 모든 개발 활동을 복제하는 작업 일지가 아니라 설계 기준과 세션 인수인계를 보존한다. 정확한 코드 변경 이력은 Git이, 검토와 논의는 issue와 pull request가 담당한다.

- 아키텍처·기능 설계 문서: 현재 구조, 장기 정책과 데이터 경계의 기준이다.
- 로드맵: 우선순위, 예정 작업과 보류 항목만 관리한다.
- 활성 실행 계획: 현재 상태, 확정된 결정, 검증 결과, 위험과 다음 시작점을 관리한다.
- 완료 실행 계획: 최종 결과, 장기적으로 필요한 결정, 최종 검증과 남은 위험만 보존한다.

같은 설명을 여러 문서에 복사하지 않는다. 기준을 소유한 문서에 상세 내용을 두고 로드맵과 실행 계획에서는 상대 링크로 참조한다. 한 패키지 안에서 한 세션에 구현과 검증을 마칠 수 있는 작은 수정은 새 문서를 만들지 않고 필요한 기존 문서만 갱신한다.

활성 실행 계획은 다음 상황에서만 갱신한다.

- 구현 단계 하나를 완료했다.
- 설계 결정, 범위 또는 다음 시작점이 바뀌었다.
- 새로운 위험, 제약 또는 미결정 사항을 발견했다.
- 검증이 실패했고 원인, 영향 또는 후속 조치를 확인했다.
- 다른 세션이나 작업자에게 인계한다.

파일을 열거나 검색한 사실, 결과에 영향이 없는 시행착오, 반복 실행한 성공 명령과 원본 로그 전체는 기록하지 않는다.

## 에이전트에 작업을 요청하는 형식

완벽한 프롬프트보다 검증 가능한 목표가 중요하다. 다음 네 요소를 가능한 범위에서 제공한다.

1. 해결할 사용자 문제 또는 원하는 결과
2. 포함 범위와 제외 범위
3. 지켜야 할 제약조건
4. 완료를 확인할 수 있는 예시나 기준

정보가 부족하면 에이전트는 저장소에서 확인 가능한 내용을 먼저 조사한다. 제품 동작이나 중요한 설계 선택이 결과를 바꾸는 경우에만 짧게 질문한다.

## 검증 하네스

로컬과 CI의 공통 진입점은 다음 명령이다.

```powershell
.\gradlew.bat verifyAll
```

이 명령은 백엔드 테스트, 모듈 경계 검증, 문서 링크 검사, 프런트 lint, Prettier 검사, TypeScript 컴파일과 프로덕션 빌드를 수행한다. 실패 시 해당 검사를 삭제하거나 우회하지 않고 원인과 재현 명령을 남긴다.

개발 중에는 변경 범위에 맞는 빠른 검사를 먼저 실행할 수 있다. 완료 보고 전에는 전체 검증을 실행한다.

## 규칙을 발전시키는 기준

다음 중 하나가 실제로 관찰될 때 규칙 후보로 기록한다.

- 같은 실수나 질문이 반복된다.
- 리뷰에서 놓치면 데이터 손상, 보안 문제, 모듈 침범처럼 비용이 큰 문제가 생긴다.
- 팀의 암묵적인 판단 기준 때문에 구현 결과가 자주 흔들린다.
- 긴 작업이 세션 사이에서 맥락을 잃는다.

규칙을 추가할 때는 다음 순서로 가장 강한 형태를 선택한다.

```text
DB 제약조건·타입 시스템
→ 테스트·정적 분석·빌드 검사
→ CI 차단
→ AGENTS.md 지침
→ 설명 문서
```

모든 실패를 새 규칙으로 만들지는 않는다. 한 번뿐인 상황은 실행 계획이나 이슈에 남기고, 반복되거나 중요한 불변조건만 공통 규칙으로 승격한다. 분기마다 또는 큰 기능 완료 후 `AGENTS.md`의 중복, 충돌, 폐기된 규칙을 정리한다.

## 현재 적용 범위와 다음 단계

현재 단계는 `AGENTS.md`를 지원하는 coding agent와 Claude Code 호환 연결, 사람 승인, 단일 검증 명령, CI 강제를 포함한다. 다음 항목은 실제 필요가 확인된 뒤 도입한다.

- 도메인별 하위 `AGENTS.md`
- 반복 작업을 위한 프로젝트 전용 Skill
- 회귀 사례 기반 에이전트 평가셋
- 자동 코드 리뷰 또는 장시간 자율 실행
- 다중 에이전트 병렬 개발

이 순서를 지키면 초기 하네스가 제품 개발보다 커지는 것을 막고, 실제 실패 데이터에 따라 필요한 장치만 추가할 수 있다.
