# 실행 계획 운영법

실행 계획은 여러 모듈에 걸치거나, 데이터 마이그레이션·외부 연동·여러 작업 세션이 필요한 변경에만 사용한다. 작은 수정에는 만들지 않는다.

진행 중인 계획은 `active/`, 완료된 계획은 `completed/`에 둔다. 파일명은 `YYYY-MM-DD-short-topic.ko.md` 형식을 사용한다. 계획은 다음 세션의 Codex가 대화 기록 없이도 이어서 작업할 수 있어야 한다.

실행 계획은 모든 활동을 기록하는 일지가 아니다. 다음 세션이 작업을 재개하는 데 필요한 현재 상태, 장기적으로 의미 있는 결정, 검증 결과, 위험과 다음 시작점을 기록한다. 정확한 파일 변경 이력은 Git에서 확인하고 같은 설계 설명은 담당 문서에 두고 링크한다.

## 활성 계획 최소 템플릿

```markdown
# 목표

사용자에게 제공할 결과와 완료 조건을 적는다.

## 범위

- 포함:
- 제외:

## 현재 상태

### 완료

- 완료한 결과

### 진행 중

- 현재 작업

### 남은 작업

- 아직 시작하지 않은 작업

## 다음 시작점

다음 세션이 가장 먼저 확인할 파일, 명령과 작업을 적는다.

## 현재 근거

관련 코드, 데이터, 문서와 확인한 사실을 링크한다.

## 작업 순서

- [ ] 검증 가능한 작은 단계

## 결정 기록

- YYYY-MM-DD: 결정과 이유

## 검증

실행한 명령과 결과, 실행할 테스트 시나리오, 수동 확인 항목을 적는다. 실패는 원본 로그 전체 대신 정확한 명령, 확인한 원인, 영향과 다음 조치를 남긴다.

## 위험과 미결정 사항

아직 결정되지 않았거나 후속 확인이 필요한 항목을 적는다.

## 진행 기록

- YYYY-MM-DD: 의미 있는 상태 변화와 다음 시작점
```

작업 중 계획과 실제 구현이 달라지면 현재 상태, 작업 목록, 결정 기록과 다음 시작점을 즉시 갱신한다. 파일을 열거나 검색한 사실, 결과에 영향이 없는 시행착오, 반복된 성공 명령은 진행 기록에 남기지 않는다.

## 완료 계획 최소 템플릿

활성 계획을 그대로 이동하지 않는다. 구현과 검증이 끝나면 세션 재개용 상태와 해결된 중간 과정을 제거하고 다음 구조로 압축한다.

```markdown
# 결과

최종적으로 제공한 동작과 완료 조건 충족 여부를 적는다.

## 변경 범위

주요 변경 영역과 관련 파일을 링크한다.

## 핵심 결정

장기적으로 참고할 결정, 이유와 제외한 대안을 적는다.

## 검증

최종 명령, 수동 시나리오와 결과를 적는다.

## 남은 위험과 후속 작업

해결되지 않은 위험과 별도 issue 또는 후속 계획을 링크한다.
```

완료 후 남은 부채를 숨기지 말고 별도 issue 또는 후속 계획으로 분리한 다음 압축한 파일을 `completed/`로 이동한다.
